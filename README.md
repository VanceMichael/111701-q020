# 职业考试场次采集服务

这是一个用于职业考试场次的本地数据采集与归档服务。当前版本从仓库自带的合成来源记录读取一页数据，经过字段规整后写入进程内目录；来源内容和规整后的记录保留独立边界，便于在不访问外部系统的情况下复现采集过程。

## 运行

需要 Node.js 20 或更高版本，不需要安装第三方依赖。

```sh
npm test
npm run build
node src/pipeline.mjs
```

测试使用项目内的合成记录；执行不需要网络、凭据或外部服务。

## 记录类型

来源页的 `items` 支持三种记录（缺省 `type` 视为 `session`）：

- `session`：场次，字段 `id`、`label`、`state`、`revision`，可选 `date`（考试日期）。
- `notice`：停考/恢复通知，字段 `id`、`notice`（`suspension` 或 `resumption`）、`sessions`（场次编号数组）、`revision`。通知只作用于点名的场次；公开名单页把同一天其他场次一并列出，也不会被波及。
- `roster`：考生名单，字段 `id`、`session`（场次编号）、`candidates`（`[{id, name}]`）、`revision`。同一 session 的名单按修订号更新。

## 状态与提醒的一致性

- 场次的生效状态由点名它的通知中修订号最高者决定；没有通知时以场次自身发布的 `state` 为准。名单页重复列出全天场次、`state` 仍是旧值，不会覆盖通知的结论。
- 场次处于停考且名单已发布时，存储层为名单中每位考生生成一条改期提醒；`pendingReschedules()` 返回主办方仍需安排改期的考生。名单先到、通知后到（或反之）都会在对账时补齐。
- 恢复通知生效后，对应提醒被撤销（`revoked`）；撤销是终态，修订号更低的旧停考通知迟到也不会让已撤销的提醒复活。修订号更高的新停考通知视为新事件，生成新提醒。
- 名单更新（更高修订号）会同步提醒：移出名单的考生提醒撤销，新加入的考生补发提醒，保持考生清单、变更提醒与来源页面一致。
